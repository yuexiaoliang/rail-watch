# 12306 数据抓取经验记录

## 核心结论

**不要依赖 `canWebBuy` 字段判断开售状态。**

`canWebBuy='N'` 不代表"未开售"，它只表示"当前不可购买"。票已售完时该字段也是 `'N'`，但 12306 网页仍然显示"候补"。

## 座位状态解析规则（按优先级）

```
raw === '有'     → '有'（有票）
raw === '候补'   → '候补'（直接返回）
raw 是数字字符串 → number（余票数）
raw === '无' 且 seatType !== 'wz' → '候补'（固定座位无票可候补）
raw === '' 或 raw === '无' 且是 wz → '--'（无此座席 或 无座不能候补）
```

## 关键踩坑

### 1. `raw=''` 空字符串 ≠ 候补

空字符串表示该车次**没有这个座位类型**（如 D6722 没有商务座），应该显示 `'--'`。

错误做法：`isOnSale && raw === ''` → `'候补'` ❌  
正确做法：`raw === ''` → `'--'` ✅

### 2. `canWebBuy='N'` ≠ 未开售

| 场景 | canWebBuy | 网页显示 | 正确处理 |
|------|-----------|---------|---------|
| 已开售，票卖完 | `N` | 候补 | `raw='无'` → `'候补'` |
| 已开售，无此座席 | `N` | `--` | `raw=''` → `'--'` |

**不要根据 `canWebBuy` 做分支判断**，直接看 `raw` 值。

### 3. 无座（wz）不能候补

`raw='无'` 时：
- 固定座位（swz/zy/ze/gr/rw/yw/yz）→ `'候补'`
- 无座（wz）→ `'--'`（无座不能候补，12306 网页上也不显示候补按钮）

### 4. API 数据 vs 网页 DOM

API 返回的数据和网页 DOM 可能不一致。例如 D6722 的 DOM 中 `[10]="有"` 按表头对应是"硬座"，但 D6722 是动车不应该有硬座。实际网页上该位置显示的是"无座有"。

**结论：从 API 原始值解析比从 DOM 抓取更可靠**，DOM 结构复杂且容易因 12306 改版而失效。

## 前端显示逻辑

### 判断候补

```typescript
// scraper 已正确标记 '候补'
const isHoubu = seatAvailable === '候补';
```

不需要 `hasAnyData` 后备逻辑。scraper 正确工作时，`'--'` 只表示"无此座席"或"未开售"，不会错误地显示候补。

### 显示优先级

```
主座位有票     → 显示票数
主座位候补     → 显示"候补"，若无座有票则追加"无座有"
无候补但无座有 → 显示"无座有"
全部无票       → 显示"无"
```
